## 当天概览

今天主要在打磨旅行足迹应用的手机端体验。Sprint 6 前期规划了 7 个功能点，实际测试下来又发现了不少手机端的适配问题，从 UI 冗余到图片上传、从视图切换到交互方式，我边测边提需求，让助手逐一排查和修复。折腾了一下午，最终 Sprint 6 功能点扩充到 12 个并全部完成。工作之外，今天也陷入了一些关于中年生活的思绪，人到这个阶段，有些问题不是靠代码就能解决的。

## 有价值的收获

- **图片上传 413 的根因是 nginx 默认限制**。折腾半天发现不是代码问题，而是 `client_max_body_size` 默认只有 1M，照片稍微大点就崩。这个教训值得记在部署清单里，以后新项目上线先检查这一项。
- **手机端拍照和相册选择需要两个独立的 input 来实现**。一开始我只想要一个按钮同时支持两种方式，试了发现 HTML 的 `capture` 属性是"强制"模式而非"可选"——带它就只能拍照，去掉就只能相册。最后方案是拆成两个按钮，各管各的，反而更清晰。
- **时间线在手机端怎么展示是个值得花时间想清楚的问题**。桌面端左右栏加竖线的经典布局在手机上完全不可用。我最终选了水平滑动卡片的方案，助手评估后说数据结构不用改，主要在 CSS 和模板上动刀，最终实现效果不错，一行 `column-reverse` 就解决了奇偶条目的视觉颠倒问题。

## 可复用经验

- **手机端和 PC 端共用的组件**统一用 `@media (max-width: 768px)` 控制差异化显示，这是今天所有修复的通用原则，改动虽多但没有影响桌面端的稳定性。以后继续坚持。
- **Web 端拍照 / 相册复用路径**已经跑通了：两个独立 file input，一个带 capture 一个带 multiple，各自触发。可以做成可复用的组件模板。
