## 可复用经验

- 确定技术需求时，先验证 CLI 工具的实际安装情况，再设计方案，避免基于错误假设推进。
- 分层委派原则：脚本底座／基础设施改动由主 agent 操刀；业务开发或不熟悉的语言/框架交给 coding agent。判断标准是「代码量小 + 边界清晰 + 已读过完整代码 → 自己改；涉及未知领域/框架 → 委派」。
- 方案落地前先评估「自己改 vs 委派」的收益比，避免重复加载上下文的额外开销。
