## 当天概览

定位了多 Agent 调度不生效的根因（配置缺失而非规则不清），并完成了课题研究系统多课题并行推进的方案评审、方案设计及 MVP 落地实现与测试。

## 有价值的收获

- **多 Agent 调度不工作的根本原因**：`subagents.allowAgents` 配置项缺失，而非规则文本不够清晰。这一发现打通了多 Agent 架构从"配置但不工作"到"真正可用"的关键卡点。
- **课题研究系统升级路径有效**：基于现有脚本底座，以最小增量方式（只改 state.js + 加两个命令 + 三个命令加参数）在一小时内完成了从方案评审、设计、落地到全量测试的全流程，验证了渐近式改造方案的可行性。
- **课题数据结构已明确**：新版 state.json 引入了别名查找、状态机严格定义、相对路径存储，`resolveProject` 支持 5 种输入匹配（id/标题/序号/别名/last），为后续课题管理提供了清晰的数据基础。

## 问题或风险

- coder agent 配置的模型（`github-copilot/mai-code-1-flash`）调用失败，多 Agent 调度链条的实际容错能力尚未得到验证。

## 可复用经验

- 诊断多 Agent 调度问题时，优先检查 `agents.yml` 中的 `subagents.allowAgents` 配置项，而非先纠结规则文本或提示词质量。

## 后续建议

- 修复 coder agent 的模型配置或备选模型，确保调度链路能跑通。
- 安排一个真实任务验证跨 Agent 调度规则能正常触发 subagent。
- 将 `subagents.allowAgents` 的配置要点纳入相关文档，避免日后重复排查。
