## 可复用经验

- 课题研究应优先走脚本底座，避免手工创建 `define`、`materials` 等文件造成流程不一致。
- 文言文阅读适合采用“全文存档 + 白话译文 + 伴读精读 + 进度记录”的组合方式，便于持续推进。
- 安装 skills 时，先装单个文本类 skill 更稳妥；确认可见性后再扩展到其他技能。
- 对 OpenClaw 的配置变更，最好同时做“写入后验证”和“重载后验收”，避免误判为已生效。
- 圆桌讨论输出可以直接转为 Markdown 并归档到 Obsidian，形成可读、可复用的知识记录。
