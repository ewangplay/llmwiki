## 当天概览

今天主要围绕课题研究系统的当前课题、素材结构和指令设计做了确认。过程中明确了当前课题对象，也识别出系统只能维护一个全局 active 课题的限制。随后进一步讨论了为指令增加 ID 参数的可行性，并倾向于采用更适合人的操作方式。

## 有价值的收获

- 明确了当前课题对象是“一个普通人怎么活才算不虚此生？”，为后续研究和写作提供了统一方向。
- 找到了当前课题已有的素材入口和三段素材摘要，说明后续可以直接在既有材料上继续整理和提炼。
- 识别出系统核心限制是全局 `state.active` 只有一份，并行研究会互相覆盖，定位到了问题根源。
- 对“添加 ID 参数”这一路线做出了可行性判断，同时提出“机器内部用 ID，人在操作时用标题/序号/关键字”的更友好方案。
- 形成了一个明确判断：研究系统的唯一性应由内部标识保障，而不应要求用户记住长 ID。
- 当前素材已经沉淀出较稳定的表达方向，后续写作有了较成熟的结构基础。

## 问题或风险

- 当前课题研究系统只支持一个全局 active 课题，存在并行研究互相覆盖的状态冲突风险。
- 如果继续让人直接记长 ID，操作成本会偏高，也容易降低使用体验。

## 可复用经验

- 内部标识应稳定且唯一，用户入口应尽量简洁、可识别。
- 在只有一个全局真相的系统里，扩展并行能力前要先处理状态隔离问题。
- 推进课题时，先确认当前对象，再确认素材入口，最后讨论指令设计，是有效顺序。

## 后续建议

- 优先推进课题研究系统的多课题状态设计，解决单 active 覆盖问题。
- 设计“标题 / 序号 / 关键字 -> 内部 ID”的映射流程，减少人直接接触长 ID。
- 继续整理当前课题素材，提炼成更适合后续写作的版本。
- 在改指令入口前，先明确 `state.active` 的替代方案或隔离机制。
