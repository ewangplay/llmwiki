## 重复模式

- **先收窄范围，再逐步展开**：原型设计先锁定三个核心模块，开发先限定前端原型，页面重构先只动布局与样式。
- **先确认依据，再开始输出或开发**：多次依赖规格说明书、设计文档、原型图、模板文件来对齐内容和样式。
- **通过分步推进降低返工**：例如选题先加素材再生成草稿；原型先 mock 接口再联调；重构先布局后样式。
- **遇到偏差先纠正方向**：无论是场地预定模块的角色理解偏差，还是 Tomcat 停止原因的误判，都体现出“先校准判断再继续”的习惯。
- **强调统一结构与风格**：无论是三个业务模块的文档输出，还是管理端页面与客户模块的交互对齐，都在追求一致性。
- **偏好把规则沉淀到文档里**：多 Agent 分工、草稿入口、开发边界等都在工作区文档中固化，减少后续重复判断。

## 趋势变化

- **从需求梳理转向原型落地**：5/6 主要是在拆模块和定模板，5/7 开始进入前端原型开发，5/9 则进一步进入页面重构与审核模块细化。

- **从概念判断转向可试运行规则**：多 Agent 方案不再停留在概念层，而是进入试运行版，且职责分层和入口分流都有了明确规则。
- **从临时处理转向长期可复用机制**：如 use mock、模板参考、文档固化、入口分流，都是在降低未来重复成本。
- **内容项目推进更成熟**：选题从素材积累逐步过渡到草稿阶段，说明写作流程已经形成较稳定的推进节奏。
