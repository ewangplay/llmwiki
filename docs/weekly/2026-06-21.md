## 重复模式

**1. 同一主题分多轮深度处理**
读后感课题未在同一天结束，而是跨时两天：周一完成成文输出，周二转化为课题并分五批加入素材后生成草稿。同一知识资产经历"快产出 → 深加工"双阶段，形成可复用的内容资产升级路径。

**2. "先验证再方案"反复被触发**
确定技术方案前需验证工具实际可用——周三发现 GitHub Copilot CLI 未安装及时止损；周四 Claude Code TUI 模式超时后排查出非交互模式才有效。问题不断复现，说明对未知工具先小验证再大规模投入的意识仍需固化为默认流程。

**3. main agent 不查现成信息就下判断**
周五反复出现：不读需求文档就重问技术栈、不查配置就判断 Agent 类型、不读源码就下 ClawSwarm 结论。这是本周最突出的低效模式，累计消耗了多次回合的沟通和纠偏成本。

**4. 分层委派原则逐步固化**
周三明确"代码量小+边界清晰+已读过完整代码→自己改，未知领域→委派 coding agent"；周五进一步修正认知为"开发走 sprint dev → Claude Code 链路，不走 coder subagent"。分层判断标准在本周经历了从原则到流程的具体化。
